# Read-only Rust review adjudication

Four independent reviewers examined the same uncommitted split worktree before the changes below. Their reports are in the pi-subagents artifact directory for workflow `86c06dba-30b6-4eab-b187-c7c3cfefe0f5` (`reviews/rust-project.md`, `reviews/rust-microsoft.md`, `reviews/rust-google.md`, `reviews/rust-skills.md`).

| Finding | Decision | Evidence / disposition |
| --- | --- | --- |
| Rust-project review: no applicable findings | No change | Reviewed new public core API; no `unsafe` added. Its test/dependency coverage exclusions were verified by the parent. |
| Microsoft + Google: retargeting `api-worker` to `api-only` leaves `*-api-worker.rs` | **Reject** | `"orders-api-worker.rs".ends_with("-worker.rs")` is true; the API-only cleanup already removes it. Added `retargeting_combined_project_to_api_only_removes_stale_binary`, which passed *before* any implementation change and builds the retargeted package. |
| Microsoft + Google: API-only cannot validate an external graph task | **Reject** | No valid `.bl` source currently produces `named_graph`: `compiler::parse` sends `process` bodies to `graph::parse_source` and sets `named_graph: None` (`src/compiler.rs:249-260`). `graph::parse_named` is unused. Existing tests `braced_project_rejects_legacy_extension_calls_before_cargo_resolution` and `legacy_extension_call_fails_before_resolving_missing_dependency` prove qualified task declarations are rejected as invalid process statements before Cargo metadata. API-only is required to validate *valid* discovered sources, not restore removed legacy task grammar. Its generated manifest intentionally omits unused task dependencies. |
| Google: external task codegen imports `runtime::{Values, Evaluate}` with worker feature off | **Reject for this change** | The external-task generator is reachable only from unused `named_graph` output; `Project::programs` cannot produce a named graph from accepted `.bl` grammar. Direct-source and generated-crate tests (59 generated cases) passed with no runtime features where intended. Moving these dormant aliases does not fix a currently valid crate. Revisit if named external tasks are explicitly reintroduced. |
| rust-skills: simultaneous consistent policy registrations race at `SELECT FOR UPDATE` of absent row | **Accept** | Added a deterministic PostgreSQL test holding a table lock until both transactions reach the insert. It failed on unique conflict. Switched to `INSERT ... ON CONFLICT DO NOTHING` followed by locked metadata comparison in the same transaction; the full PostgreSQL suite passes (36/36). Conflicting policy still rolls back registration. |
| rust-skills: huge accepted deadline overflows PostgreSQL `BIGINT` during admission/claim | **Accept** | Added a failing huge-duration registration test and reject durations above `i64::MAX / 2` with an actionable error before publishing any worker. Normal queue-origin deadlines remain covered by PostgreSQL tests. This leaves a centuries-long margin even after adding current epoch milliseconds. |

Ponytail review of the revised diff: no invented queue or worker hierarchy, extra runtime crate, or new general-purpose dependency was introduced; direct conditional features, a single SQL insert-and-check, and the existing local/remote stores remain the shortest design satisfying the approved contracts. No actionable deletion/simplification finding was identified. `Lean already. Ship.` This does not waive the required post-review verification.
