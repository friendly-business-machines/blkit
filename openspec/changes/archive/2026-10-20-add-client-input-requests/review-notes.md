## 6.1 Representative request-transition/fan-out load check

Measured 2026-10-19 on WSL2/Linux x86_64, Ryzen 9 5900X (24 logical CPUs), 31 GiB RAM, disposable PostgreSQL 17.6 test container (`max_connections=100`), in-process Axum routers and no TLS/ingress. Reproduce with `cargo test -p blkit-dev-harness --test postgres postgres_request_transition_fanout_load_check -- --nocapture`; all six original and two corrected-fixture runs passed. The corrected test at `tools/dev-harness/tests/postgres.rs` uses a deadline-free local graph copy and asserts all 48 claimed rows have no persisted graph deadline; the original directly created rows also had no persisted deadline. The 120-second claim lease is a separate fence.

Per run: two API replicas with one dedicated LISTEN session each, one SSE subscription on each replica for each of 24 watched instances; 24 unwatched instances; one worker; eight concurrent initial checkpoint commits per watched/unwatched batch (watched first), then 24 accepted response POSTs at up to eight concurrent, alternating replicas. Verify both replica hints for each watched request creation/answer, and verify an unchanged ordinary checkpoint emits **no** hint. Measurements: 24 watched commits, 24 unwatched commits, 24 HTTP response acknowledgments, 96 SSE deliveries. Times are monotonic milliseconds: commit includes pool checkout/transaction/trigger/commit; POST includes HTTP dispatch through committed 202; SSE is **from before write/POST to body delivery**, not post-commit latency. Sorted-sample median, nearest-rank p95 and maximum were recorded. No approved product latency SLO or connection budget was violated, so no unapproved outbox/fast-path optimization was made. Their P2 performance suggestions are accepted for simple bounded-copy/query elimination, **not** as explanations for the separate watched-commit p95 gap. The rust-skills P1 is independently confirmed by the existing blocked-registration fixture. A reviewer may challenge an implementation or a source claim during fix review; parent will adjudicate that with tests. **P1 fix review round 1:** Commit `4449fd8` moved DB awaits outside the global watcher map and added a deterministic blocked-A/active-B regression; 75 PostgreSQL tests passed. Independent reviewer found a remaining saturation case: 32 duplicate A hint jobs queue on A's per-instance mutex, disabling `incoming.recv()` and preventing B's hint until A unblocks (`distributed.rs:251–264`). The two-second renewal tick also spawns one job per watcher without the 32-job limit (`:274–283`); >32 watchers can block hint intake/pool checkout. **Accept both findings**, demand a bounded fair/coalesced per-instance hint/renewal schedule with a focused saturation regression (32 A hints while B stays live, >32 watcher renewal), preserving reliable resync and bounded memory. Do not mark 6.3 or integrate until re-reviewed.

**P1 fix review round 2:** Commit `9164d14` coalesces per-instance hints and bounds renewals to two jobs with a transaction-local 750ms PostgreSQL lock timeout. The 32-duplicate-A and 36-watcher/B-expiry regressions and 77 PostgreSQL tests pass. Fresh reviewer found another valid P1 schedule: two A renewals time out, then queued A subscriptions take their per-instance `order` locks; Retry jobs block awaiting those locks while occupying both renewal slots, preventing B lease repair until expiration (`distributed.rs:300–332,388–397`). **Accept:** busy-order retry must defer without using an active slot, with bounded no-hot-loop retry and deterministic two-A-subscription/B-expired regression. Reviewer also found a P2 test mismatch (`postgres.rs:6269–6276`): simultaneous duplicate NOTIFYs may legally coalesce into one hint; **accept** adjusting the test to require delivery after a second hint sent *after* consuming the first, or to assert only authoritative-state coalescing. Preserve no-replay/duplicate-hint contract. Fix/re-review before branch integration.

**P1 SSE fix adjudicated complete:** `bf8d3b7` defers order-busy Retry to a later tick, retains one scheduled renewal per instance and no hot spin; deterministic two-A/expired-B test red before, green after, 78 PostgreSQL tests pass. It also separates the duplicate-hint sends by consumption. Independent read-only re-review found no issue. The accepted P2 Rust fixes were committed as `6e5ce95`: post-runtime drop no longer panics, empty-request graphs skip answer reads, reply completion shares `Arc<NamedRegistry>` and borrows JSON input. The new drop test was red before and green after; 69 engine, 4 concurrency, and 79 PostgreSQL tests passed, plus fmt/standard Clippy. A fresh independent reviewer inspected `b03bc12..6e5ce95`, found all four addressed and no new issue; the full suite remains a parent gate.
